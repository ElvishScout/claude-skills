# 提示词与 Skill 写作规范

编写或修改系统提示词（System Prompt）、任务指令及 `SKILL.md` 时，遵循以下原则与工作流。

## 核心原则

### 1. 从当前状态出发，不留历史补丁

提示词只描述最终期望的目标状态与行为规范，不保留多轮对话的演进过程。

- **全量融合**：多轮迭代时，将新要求直接融入对应章节并重写该段落，不在文末追加修正说明或防御性叮嘱。
- **独立自洽**：删除仅在当前对话上下文中成立的指代与对比，确保提示词在全新会话中可直接生效。

### 2. 提炼普遍规律，不把个例写死

用户反馈往往针对某一次具体输出的问题。写提示词时先归纳原因，再写入通用规则。

- **抽象判断标准**：遇到具体问题样本时，分析背后的边界条件或分类逻辑，将通用判断标准写进正文，不把单一输入或特定字面值写成硬编码规则。
- **克制使用示例**：仅在抽象规则本身难以界定边界、或需要固定复杂输出格式时才附带示例。

### 3. 正向陈述，克制强调与否定

靠结构位置与逻辑清晰度传递重点，而非靠情绪化措辞或反复叮嘱。

- **先说做什么**：直接陈述目标做法与判断依据；仅在边界容易混淆时，用简短句子说明“不做什么”。
- **一处说清**：同一约束只放在最归属的模块下写一次，不在前言、步骤、结尾中反复重申。
- **去除亢奋强调**：不使用夸张的禁止词、程度副词、连续感叹号或全大写来施压。

### 4. 平铺直叙，剔除 AI 腔

以高信息密度的说明文写作，句子只承载目标、条件与动作，不加修辞包装。

- **用具体标准代替抽象形容**：不用笼统的质量修饰词或恭维式人设铺垫，直接写明需要检查的维度、评判标准或执行步骤。
- **陈述事实，不造修辞结构**：不使用比喻、排比、对仗或递进句式来凑节奏；有几条规则就平实列出几条。
- **只给指令，不讲道理**：直接给出规则与边界，不铺垫背景意义，也不解释遵守规则的价值。

## 编写与修改工作流

1. **划分结构**：按职责组织模块（如目标与边界、工作流与规则、输出格式）。简单提示词直接分段，不强套固定模板。
2. **重整而非追加（多轮修改时）**：
   - 通读现有全文，定位新需求归属的模块。
   - 若逻辑发生变更，直接替换旧规则；若多次修改导致条目零散或交叉，合并同类项并重排顺序。
   - 全文通读一遍，删去残留的旧规则、重复约束和修饰性废话。
